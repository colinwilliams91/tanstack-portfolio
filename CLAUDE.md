# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server at http://localhost:3000
- `npm run build` — Production build (output: `dist/client`)
- `npm run preview` — Preview production build
- `npm run lint` — Type check only (`tsc --noEmit`). There is no test runner configured.

The ESLint config (`eslint.config.ts`) only enables `@tanstack/eslint-plugin-query` rules and is not wired to an `npm` script.

## Stack

TanStack Start (full-stack React framework) + TanStack Router (file-based, code-gen'd routes) + TanStack Query (data fetching/cache) + Tailwind CSS 4 + daisyUI 5 + React 19. Deployed on Netlify via `@netlify/vite-plugin-tanstack-start` (Node 22.12). Vite injects `__BUILD_VERSION__` and `__BUILD_COMMIT__` from `DEPLOY_ID` / `COMMIT_REF` / `GITHUB_SHA`.

## Architecture

**Routing.** File-based under `src/routes/`. `src/routeTree.gen.ts` is generated by TanStack Router — never edit it by hand. Routes use `defaultPreload: "intent"` and prefetch query data via route loaders (e.g. `queryClient.ensureQueryData(...)` in `src/routes/blogs/index.tsx`). Dynamic segments use `$paramName` filenames.

**Container / Presenter pattern.** Every page splits into `*.container.tsx` (data + hooks + side effects) and `*.presenter.tsx` (pure JSX). Containers consume `QUERY_OPTIONS` from `src/constants/queries/query-options.ts`. View-level prop types live in co-located `abstract/index.ts` files; entity/DTO/API-contract types live in `src/types/`.

**Folder shape per feature (`about`, `blogs`, `home`, `projects`).**
- `list/` — list-view container + presenter
- `detail/` — single-item container + presenter
- `abstract/index.ts` — Props/View interfaces

Shared UI is in `src/components/shared/` (Header, Footer, Icon, Menu, SearchBar, plus `badges/`, `diagnostics/`, `errors/`, `themes/`). The `Icon` component reads from `public/sprite.svg` and is typed by the `IconName` union in `src/components/shared/abstract/index.ts` — when adding a new icon, update both the sprite and that union.

**Theming.** Two daisyUI themes: `abyss` (default + prefers-dark) and `winter`. A server middleware in `src/start.ts` (`themeMiddleware`) reads/sets the `theme` cookie before render so SSR matches the client's data-theme; `src/providers/ThemeContext.tsx` then reads that same cookie on the client. Don't add a third theme without updating both `THEMES` (`src/constants/themes.ts`), `Theme` type, the middleware, and `app.css`.

**Data sources.** External public APIs only (no backend):
- Dev.to articles for blogs (`src/handlers/fetch/blogs.ts`). The detail endpoint inverts `tags`/`tag_list` vs. the list endpoint — `fetchBlogById` normalizes them. Bug tracked at forem/forem#22659; remove the workaround when fixed.
- GitHub `/users/.../repos` for projects (`src/handlers/fetch/projects.ts`).

All URLs are centralized in `src/constants/public-api-urls.ts`. Query keys/options live in `src/constants/queries/`. Default React Query cache: `staleTime` 5 min, `gcTime` 30 min (see `src/constants/router.ts`).

**Styling.** Tailwind CSS 4 + daisyUI 5 are configured entirely in `src/styles/app.css` via `@plugin "daisyui" { themes: abyss --default --prefersdark, winter; }`. **Do not create a `tailwind.config.js`** — Tailwind v4 does not use one. Custom component classes (`nav-link`, `tech-base`, `tech-tile`, `card` overrides, fixed body gradient/grid) are defined in `app.css`. A detailed daisyUI 5 reference lives at `.github/instructions/daisyui.instructions.md`.

**Path aliases** (`tsconfig.json`):
- `~/*` → `src/*`
- `~c/*` → `src/components/*`
- `~a/*` → `src/assets/*`
- `~s/*` → `src/components/shared/*`
- `~t/*` → `src/types/*`

## Conventions

- Container/Presenter split is enforced across all feature areas — match it when adding pages.
- Co-locate Props types in `abstract/index.ts`; reserve `src/types/` for entity / DTO / API-contract types.
- When adding a new query, add `QUERY_KEYS` and `QUERY_OPTIONS` entries, then consume `QUERY_OPTIONS.X.Y` from the container (and from the route loader if the page should preload).
- Feature flags go through `src/constants/feature-flags.ts` + `useFeatureFlag` hook.
- The fetch handlers contain `import.meta.env.DEV` diagnostic logging marked `TODO: remove` — leave it alone unless explicitly cleaning it up.
- daisyUI semantic colors (`primary`, `base-100`, `accent-content`, etc.) over raw Tailwind colors so themes can swap.
